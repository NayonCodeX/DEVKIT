# APK Build Guide — Native Kotlin WebView

This guide walks you through building the DEVKIT Android APK from source. The app is a **native Kotlin WebView wrapper** that bundles the entire DEVKIT PWA (Next.js static export) inside the APK at `assets/www/`, so it runs **100% offline** — every tool, theme, and the Bangla/English UI work without any internet connection.

---

## How it works

1. The DEVKIT Next.js app is exported as a static site into `devkit-android/app/src/main/assets/www/` (`index.html` + the `_next/` JS/CSS bundle).
2. The native Kotlin `MainActivity` hosts a `WebView` and uses Google's `WebViewAssetLoader` (from `androidx.webkit`) to serve those bundled files under the virtual origin `https://appassets.androidplatform.net/`.
3. The WebView loads `https://appassets.androidplatform.net/assets/www/index.html`, which behaves exactly like loading from a real HTTPS server — every relative URL in the Next.js bundle resolves correctly.
4. The result is a release-signed APK that ships the entire PWA offline, in a single installable file.

**Why a native WebView and not a Bubblewrap TWA?** A TWA loads the PWA from a remote HTTPS URL, so it requires the app to be deployed and online. The native WebView bundles the entire app inside the APK, so it works fully offline — which is what most DEVKIT users want.

---

## Prerequisites

- **JDK 17** (Temurin 17.0.13+ recommended — Gradle 8.7 is not compatible with JDK 21+)
- **Android SDK** with `platform-tools`, `platforms;android-34`, and `build-tools;34.0.0`
- **Gradle 8.7** (the wrapper `devkit-android/gradlew` will use it; we invoke the system `gradle` here)
- A release keystore (see "Generate a release keystore" below) — the project's keystore is **not** committed

---

## Step 1 — Export the DEVKIT PWA into `assets/www/`

The bundled `assets/www/` directory is already committed (it was generated by `next build` + a static-export patch). To regenerate it from the latest DEVKIT source:

```bash
# From the project root
bun run build                      # produces .next/ with the static export
./scripts/patch-routes-static.sh   # moves the static export into devkit-android/app/src/main/assets/www/
```

The result is `devkit-android/app/src/main/assets/www/index.html` plus the `_next/static/` bundle. You can verify it:

```bash
ls devkit-android/app/src/main/assets/www/
# 404.html  _next/  _not-found/  devkit/  devkit-sw.js  index.html  index.txt
```

---

## Step 2 — Generate a release keystore (one-time)

The committed `.gitignore` excludes all `*.keystore` files. To sign your own build, generate one:

```bash
cd devkit-android
keytool -genkeypair \
  -keystore devkit-release.keystore \
  -alias devkit \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass devkit1234 -keypass devkit1234 \
  -dname "CN=DEVKIT, OU=NCX, O=NayonCodeX, L=Dhaka, ST=Dhaka, C=BD"
```

Then make sure `app/build.gradle.kts` points at it (it already does by default):

```kotlin
signingConfigs {
    create("release") {
        storeFile = file("devkit-release.keystore")
        storePassword = "devkit1234"
        keyAlias = "devkit"
        keyPassword = "devkit1234"
    }
}
```

> **Note:** The published v1.0.3 APK on GitHub was signed with the official NayonCodeX keystore. If you sign with your own keystore, your APK will **not** install over the official one — users must uninstall the official DEVKIT first. This is by design (keystores are private).

---

## Step 3 — Configure `local.properties`

Tell Gradle where the Android SDK lives:

```bash
echo "sdk.dir=/home/$USER/android-sdk" > devkit-android/local.properties
```

(`local.properties` is gitignored — it is per-machine.)

---

## Step 4 — Build the release APK

```bash
cd devkit-android
./gradlew :app:assembleRelease      # or: gradle --no-daemon :app:assembleRelease
```

The output lands at:

```
devkit-android/app/build/outputs/apk/release/app-release.apk
```

Typical size: **~6.5 MB** for the v1.0.3 build.

---

## Step 5 — Verify the build

```bash
APK=app/build/outputs/apk/release/app-release.apk

# 1. Signature check
$ANDROID_HOME/build-tools/34.0.0/apksigner verify --verbose $APK
# Expected: "Verifies" + "Verified using v2 scheme (APK Signature Scheme v2): true"

# 2. Package + version info
$ANDROID_HOME/build-tools/34.0.0/aapt dump badging $APK | head -3
# Expected: package: name='com.nayoncodex.devkit' versionCode='4' versionName='1.0.3' ...

# 3. _next bundle included?
unzip -l $APK | grep -c "_next"
# Expected: 32 (or similar non-zero count)

# 4. Launcher icons included?
$ANDROID_HOME/build-tools/34.0.0/aapt dump resources $APK | grep "ic_launcher"
# Expected: lines for mipmap/ic_launcher + mipmap/ic_launcher_round at all densities

# 5. SHA256 (for the release notes)
sha256sum $APK
```

---

## Step 6 — (Optional) Publish to GitHub Releases

Tag the release, push, then upload the APK as a release asset:

```bash
git tag v1.0.x
git push origin v1.0.x

# Create the release (use a JSON file to avoid shell-escaping issues with backticks)
curl -X POST -H "Authorization: Bearer $GH_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  --data @release.json \
  https://api.github.com/repos/NayonCodeX/DEVKIT/releases

# Upload the APK as an asset of that release
curl -X POST -H "Authorization: Bearer $GH_TOKEN" \
  -H "Content-Type: application/vnd.android.package-archive" \
  --data-binary @$APK \
  "https://uploads.github.com/repos/NayonCodeX/DEVKIT/releases/$RELEASE_ID/assets?name=DEVKIT-v1.0.x.apk"
```

## Troubleshooting

### `Could not resolve org.jetbrains.kotlin:kotlin-reflect` / HTTP 429 from Maven Central

Maven Central rate-limits anonymous downloads. The project's `settings.gradle.kts` already puts the **Aliyun mirror** first in the repository list, which bypasses the rate-limit. If you still hit 429s, wait ~2 minutes and retry — the rate-limit window is short.

### `Keystore file '...app/devkit-release.keystore' not found`

The `file("devkit-release.keystore")` call in `build.gradle.kts` resolves relative to the `app/` module directory, so put the keystore at `devkit-android/app/devkit-release.keystore` (not the project root).

### `Type mismatch: inferred type is Uri? but Uri was expected`

This was a compile error in early v1.0.3 drafts where `shouldInterceptRequest` was passed `request?.url` directly. The fix is to null-check first:

```kotlin
val url = request?.url ?: return null
return assetLoader.shouldInterceptRequest(url)
```

### App "opens and immediately closes" on phone

This was the v1.0.1/v1.0.2 crash. Root cause: the app loaded the PWA from `file:///android_asset/www/index.html`, but Next.js's `./_next/...` relative paths don't resolve reliably on `file://` URLs. The v1.0.3 fix is `WebViewAssetLoader`, which serves the same files under `https://appassets.androidplatform.net/` so the paths resolve like a real web server. If you see this crash again, verify that `MainActivity.setupWebView()` is still using the asset loader and that `LOCAL_MODE = true`.

### `App not installed` when upgrading

Two causes:
1. The previous version used a different package name (v1.0.0–v1.0.2 used `com.nayoncodex.devkit.debug`; v1.0.3 uses the clean `com.nayoncodex.devkit`). Fix: uninstall the old version first.
2. The APK was signed with a different keystore than the one already on the phone. Fix: sign with the same keystore, or have the user uninstall first.
